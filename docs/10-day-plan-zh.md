# Quotation Preparation：四人团队 10 天开发计划

## 1. 最终判断

10 天内最值得做的不是继续扩大产品数量，而是把现有数据做成一个**有证据、会追问、能计算、可复现、懂得拒绝错误要求的报价 Agent**。

项目主线用一句话说明：

> 销售人员输入一段不完整的客户询价，Agent 主动补齐需求，从有出处的产品目录中筛选合适型号，用确定性工具计算价格，经过人工确认后生成可追溯、可修订的报价 PDF。

目前的数据量已经足够支撑比赛。今天完成数据冻结后，不再下载新的产品类别、实时价格或库存数据，把时间用于 Agent 工作流、证据展示、报价版本和评估。

## 2. 评委能记住的四个亮点

### 亮点一：每个关键规格都能回到原始证据

候选产品旁显示规格来源。点击 `USB-C video`、`90 W Power Delivery`、分辨率等字段，可以看到对应 Dell 手册、页码和证据摘录。系统不会只说“依据产品资料”，而是把证据直接展示出来。

### 亮点二：Agent 会发现需求中的歧义和冲突

“需要 USB-C”并不清楚：客户可能只要数据口，也可能要求同一根线传视频并给笔记本供电。Agent 必须先追问用途和最低供电功率，再推荐产品。

演示中用 U2724D 制造一个容易出错的场景：它有 USB-C 数据接口，但不支持 USB-C 视频输入。系统应拒绝把它当成一线连接显示器，并在用户允许时推荐 U2724DE。

### 亮点三：模型负责理解，工具负责事实和金额

Bedrock 模型只负责提取需求、决定何时追问和调用哪个工具。产品、价格、折扣限制和总额都由后端工具返回。单价不用模型生成，金额不用模型心算。

三个冻结工具为：

- `search_products`：按结构化条件筛选产品；
- `get_product`：读取一个 SKU 的规格、模拟价格和字段证据；
- `calculate_quote`：按固定规则计算草稿金额和预算差额。

### 亮点四：报价是可复现的业务文档

报价 v1 保存当时的产品、价格和规则快照。修改数量或显式选择“按最新价格重算”时生成 v2，并显示条目、数量和总额差异。重新打开 v1 时金额不变，证明它不只是一次聊天结果。

## 3. 10 天范围

必须完成的纵向流程：

```text
客户询价
  → Agent 提取已知信息
  → 对缺失或含糊字段追问
  → search_products
  → 展示候选及规格证据
  → 用户确认产品、数量和折扣
  → calculate_quote
  → 保存报价版本
  → 导出 PDF
  → 修改需求并生成新版本
```

四个硬门禁：

| 门禁 | 时间 | 通过标准 |
|---|---|---|
| Gate 0：数据冻结 | Day 1 中午 | 6 份 PDF、12 个产品、价格、规则、证据和评估集通过校验；人工抽查完成 |
| Gate 1：纵向流程 | Day 3 结束 | 一条真实询价完成追问、查询、确认和正确计价，可暂时使用简单页面 |
| Gate 2：完整产品 | Day 7 结束 | 证据跳转、报价 v1/v2、PDF 和 AWS Bedrock 工作流全部连通 |
| Gate 3：功能冻结 | Day 8 结束 | 异常场景和评估跑通；之后只修 bug、录视频和整理提交物 |

机器校验已经完成，但提交前需要一名队员做一次独立抽查。控制在 30–45 分钟内：

2. 在 `field_evidence.csv` 中每个产品抽 2 个字段；

### 4.3 不需要再下载的数据

- **不下载更多显示器或键鼠。** 12 个产品已经覆盖尺寸、分辨率、USB-C 视频和 65/90 W 供电差异。
- **不下载实时市场价格。** 价格随地区和时间变化，反而难以复现；比赛使用带版本号的模拟价格更合理。
- **不编造库存和交期。** 当前没有可靠来源，因此 Agent 应回答“需人工确认”，不能承诺有货或次日送达。
- **不下载真实客户记录。** 这会引入隐私问题，演示客户和询价继续使用合成数据。
- **不使用留出集做提示词或知识库。** `enquiries_holdout.jsonl` 只在 Day 7 首次验收时使用。

如果比赛后要继续产品化，再接公司 ERP/CRM 的真实价格、库存、客户等级和审批规则；这些不属于本次 10 天交付范围。

## 7. AWS 实现边界

推荐架构：

```text
Web UI
  → FastAPI backend
      → Amazon Bedrock Converse（理解需求、追问、选择工具）
      → 本地工具层（search_products / get_product / calculate_quote）
          → catalog.json 或 SQLite（规格、证据、模拟价格、规则）
      → Quote DB（报价及版本快照）
      → PDF generator
      → 可选 S3（数据包、PDF 或部署静态资源）
```

10 天内优先使用 Bedrock Converse 的 tool use。除非团队已经熟悉 Bedrock Agents，否则不要临时增加 Action Group、Knowledge Base、向量数据库或复杂多 Agent 编排。现有 12 个产品可以通过结构化工具精确查询，向量检索不会提高结果质量。

AWS 侧只需要：

1. 一个在所选 AWS Region 中可调用、支持 Converse 与 client-side tool use 的 Bedrock 模型和固定模型 ID；
2. 后端使用的最小权限 IAM 身份；
3. CloudWatch 日志中隐藏提示词里的敏感字段；
4. 可选的私有 S3 桶；本地开发阶段可以直接读取 `data/agent/catalog.json`。

Day 1 先按 AWS 官方的 [tool use 说明](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use.html) 和 [模型兼容性列表](https://docs.aws.amazon.com/bedrock/latest/userguide/models.html) 核对账户、Region 和模型能力，避免到 Day 4 才发现选定模型不能调用工具。

## 8. 三条完整演示故事

### Story A：模糊询价变成可确认报价

客户：“We need 8 monitors with USB-C. Budget SGD 2,500.”

Agent 不立即报价，而是追问 USB-C 是否需要视频和笔记本供电。客户补充至少 65 W、23.8 英寸 FHD 可接受。系统推荐 P2425HE，展示 90 W 证据，计算 8 台 SGD 2,312。客户改成 10 台，系统生成 v2 并显示超预算 SGD 390，而不是悄悄替换成不满足要求的型号。

### Story B：发现规格陷阱

客户指定 4 台 U2724D，并要求一根 USB-C 线完成视频和 90 W 供电。系统从手册证据发现该型号的 USB-C 上行口是 data-only，阻断错误报价；用户同意后，系统提出 U2724DE 并重新计算。

### Story C：守住业务规则

客户要求 5 台 S2725QC、6% 折扣并保证明天交货。系统拒绝超过 5% 的模拟折扣上限，也不会在没有库存和物流数据时承诺交期。它可以生成“待审批/待确认”草稿，但不能把它表现成已批准报价。

三条故事覆盖成功路径、事实冲突和政策边界，足以支撑 30 分钟视频，不需要更多产品类别。

| 5:00–13:00 | Story A 完整演示：追问、证据、报价、v1/v2、PDF | D + B |
| 13:00–17:00 | Story B：USB-C data-only 规格陷阱 | A + C |
| 17:00–20:00 | Story C：折扣上限、库存未知、人工升级 | C |
| 20:00–24:00 | AWS 架构和一次真实 tool trace | C + B |
| 24:00–27:00 | 数据来源、字段证据、dev/holdout 方法和真实结果 | A |
| 27:00–29:00 | 失败回退、报价快照和审计能力 | B + C |
| 29:00–30:00 | 实测价值、当前范围和下一步接 ERP/CRM | D |

视频中不要连续讲幻灯片。每个技术观点后紧跟一个可见证据：工具调用、PDF 页码、金额重算、版本差异或失败提示。

## 10. 验收指标

Day 7 开始对 holdout 首次评估，至少记录：

| 指标 | 计算方式 | 建议门槛 |
|---|---|---:|
| 必填字段追问正确率 | 缺字段案例中正确追问数 / 缺字段案例数 | ≥ 90% |
| 产品筛选正确率 | 正确候选集合案例数 / 可判定案例数 | ≥ 90% |
| 金额正确率 | 与独立预期金额完全一致的报价数 / 可报价案例数 | 100% |
| 政策违规阻断率 | 超折扣、未知库存/交期案例中被阻断的比例 | 100% |
| 证据覆盖率 | 展示的关键规格中可打开来源和页码的比例 | 100% |
| PDF 一致率 | 页面、数据库快照和 PDF 金额一致的比例 | 100% |

效率提升只能来自实测。选择 5 个相同询价，让一名队员分别用人工流程和 Agent 流程完成并计时，报告样本量、中位数和范围，不写预设的“节省 80%”。

## 11. 明确不做

- 扩展到 30 个产品；
- 键鼠、打印机和其他新品类；
- 登录、多租户和复杂权限；
- 实时电商价格、真实库存和配送计算；
- 税费、多币种和复杂审批流；
- 真实发送邮件或创建采购订单；
- 模型微调、复杂多 Agent 和向量数据库；
- 为视频效果制作与核心能力无关的动画。

任何新需求先问：它是否直接改善三条演示故事或六项验收指标？如果不能，就放到赛后路线图。

## 12. 每天收工规则

每天结束前用 DEMO-01 跑一次端到端 smoke test，并保存当天结果。发现询价无法继续、金额不一致或证据打不开，当天修复；不把集成问题留到 Day 8。Day 8 功能冻结后，只接受阻断演示、金额错误、数据错误和凭据泄露问题。
